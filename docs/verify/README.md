# Контрольные документы: как проверить расширение самому

Пять файлов с вымышленными данными. По ним можно за несколько минут увидеть, что расширение маскирует, что оставляет открытым и где может ошибиться. Все имена, номера и адреса придуманы; ИНН, СНИЛС, ОГРН и счета посчитаны с правильными контрольными цифрами, но принадлежат несуществующим людям и компаниям.

| Файл | Что внутри | Что должно произойти |
| --- | --- | --- |
| [`01-dogovor.docx`](01-dogovor.docx) | договор оказания услуг: заказчик — физическое лицо, исполнитель — ООО | персональные данные и реквизиты заменены метками, название ООО и номер договора остаются |
| [`02-reestr-klientov.xlsx`](02-reestr-klientov.xlsx) | таблица из четырёх клиентов: ФИО, дата рождения, телефон, e-mail, ИНН, СНИЛС | все 24 значения заменены, заголовки столбцов остаются |
| [`03-spravka.pdf`](03-spravka.pdf) | справка с места работы, PDF с текстовым слоем | в чат уходит `03-spravka.anon.md` — текст справки с метками |
| [`04-pasport-foto.png`](04-pasport-foto.png) | картинка «паспорт (образец)» | панель пишет «Формат .png не проверяется на персональные данные»; файл уходит только по кнопке «Загрузить как есть» и уходит без изменений |
| [`05-trudnye-sluchai.docx`](05-trudnye-sluchai.docx) | служебная записка с двумя трудными случаями | обычные данные заменены; фамилия без имени и иностранное имя могут остаться — их маскируют вручную |

Ожидания в машиночитаемом виде — [`expected.json`](expected.json). Файлы создаёт скрипт [`scripts/gen-verify-docs.mjs`](../../scripts/gen-verify-docs.mjs).

## Как проверить

Документы лучше прикладывать не в настоящий чат: ChatGPT и другие сервисы загружают вложение сразу, ещё до отправки сообщения. Подойдёт любая страница с полем выбора файла, например своя:

1. Поставьте расширение (раздел «Установка» в [README](../../README.md#установка)).
2. Создайте папку с файлом `index.html`, в котором есть строка `<input type="file" multiple>`, и запустите в ней `python3 -m http.server 8000`.
3. Откройте `http://localhost:8000`, в меню расширения нажмите «Добавить localhost:8000», подтвердите запрос доступа и включите «Перехват загрузки».
4. Выберите в поле файлы из этой папки — по одному или все сразу. Откроется панель расширения.
5. Сверьте найденное с таблицами ниже: вкладка «Сущности» — список находок, вкладка «Текст» — документ с подсветкой.
6. Нажмите «Анонимизировать и загрузить», затем на экране «готово» — «Скачать результат» и откройте обезличенный файл: в нём должны быть метки вместо значений из таблиц.

Проверить можно и без браузера — тем же конвейером, что работает внутри расширения (анализ и замена с настройками по умолчанию):

```sh
node scripts/gen-verify-docs.mjs --check                                         # без модели NER
NER_MODEL_DIR=<каталог распакованного пакета модели> node scripts/gen-verify-docs.mjs --check   # с моделью
```

Скрипт печатает по каждому значению «замаскировано» или «пропущено» и метки, которые оказались в результате. Код выхода 1 — если осталось открытым значение, которое должно маскироваться всегда.

Метки нумеруются по порядку внутри отправки: первое ФИО — `[ФИО_1]`, второе — `[ФИО_2]`; одно и то же значение везде получает одну метку. Ниже номера указаны для случая, когда файл отправлен один.

## 04-pasport-foto.png — картинка

Текст на картинках расширение не распознаёт (распознавание сканов запланировано на 0.6). Поэтому картинка не обезличивается, но и молча в чат не уходит: панель показывает «Формат .png не проверяется на персональные данные». Дальше выбор за вами: «Загрузить как есть» отправит файл без изменений, «Отмена» — ничего. Если картинку приложить вместе с договором, договор обезличится, а картинка уйдёт, только если нажать «Загрузить как есть» на её вкладке.

Если вы регулярно отправляете картинки и не хотите отвечать на вопрос каждый раз, впишите `png, jpg` в настройках, раздел «Обработка», поле «Не спрашивать о файлах с расширениями». Тогда такие файлы уходят сразу и без проверки.

## 05-trudnye-sluchai.docx — трудные случаи

| Значение в документе | Категория | Метка |
| --- | --- | --- |
| Захарова Елена Павловна | ФИО | `[ФИО_1]` |
| +7 (921) 444-33-22 | телефон | `[ТЕЛ_1]` |
| logist@example.net | e-mail | `[EMAIL_1]` |
| Лагунов («Документы забрал Лагунов») | ФИО | **может пропустить — замаскируйте вручную** |
| Tenzing Norbu («Сверку остатков провёл Tenzing Norbu») | ФИО | **может пропустить — замаскируйте вручную** |

Почему пропуск возможен. Одиночную фамилию человека, который нигде в документе не назван полностью, правила и словари не находят — это умеет только модель NER, и то не всегда. Иностранное имя, которого нет в словарях, без модели не находится, а модель на нём может ошибиться.

Как замаскировать вручную: в панели откройте вкладку «Текст», выделите фамилию или имя, выберите «Анонимизировать как» → «ФИО» и нажмите «Применить». Все вхождения этого значения получат одну метку.

## Результат прогона (версия 0.5.2, 07.11.2026)

- **Конвейер ядра без модели NER** (`node scripts/gen-verify-docs.mjs --check`): в четырёх обезличиваемых документах замаскированы все 52 обязательных значения, открытыми остались только значения, которые по умолчанию не маскируются (организации, номер договора, заголовки столбцов). Трудные случаи: «Лагунов» и «Tenzing Norbu» пропущены.
- **С моделью NER 1.2.1** (`NER_MODEL_DIR=…`): то же; «Лагунов» найден и замаскирован, «Tenzing Norbu» пропущен.
- **Через расширение** (e2e `tests/e2e/guard-052.spec.js`, тест «контрольные документы», лёгкая сборка без модели): все пять файлов одной отправкой; у картинки — «Формат .png не проверяется на персональные данные»; после «Анонимизировать и загрузить» сайт получил четыре обезличенных файла без единого обязательного значения, картинку — нет (на ней не нажали «Загрузить как есть»).

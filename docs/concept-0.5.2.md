# Концепция версии 0.5.2: сторож не пропускает файл молча

Повод — внешний разбор проекта 07.11.2026. Автор разбора правильно понял главное: DOCX Anonymizer — не программа для предварительного обезличивания, а сторож между сотрудником и чатом с ИИ. Защита встроена в саму отправку файла и не зависит от того, вспомнит ли человек про обезличивание. README об этом говорит невнятно: первый абзац — перечень форматов и функций.

Разбор показал и пробел в самой идее сторожа: файл неподдерживаемого формата (картинка, ZIP, `.doc`, `.rtf`) сейчас уходит в чат молча. Для сторожа это неверно — фото паспорта опаснее любого договора.

## Решения владельца (07.11.2026)

1. **README начинается с того, что это и что это не.** Сторож между человеком и ИИ; сценарий из семи шагов (прикрепил договор, забыл обезличить, расширение перехватило, нашло данные, отправило копию с масками, ответ восстанавливается, пропуски можно замаскировать вручную); честная оговорка: полного распознавания не гарантируем, поэтому есть проверка и ручное маскирование, распознавание улучшаем. Отдельный раздел «Что расширение не закрывает».
2. **Предупреждение на любой файл.** Файл, который расширение не умеет проверять, не уходит без явного выбора человека — так же, как сейчас скан PDF: «Формат не проверяется на персональные данные» и кнопка «Загрузить как есть». Картинки тоже предупреждаются. В настройках — список расширений «не спрашивать», по умолчанию пустой.
3. **Поле выбора файла очищается сразу после перехвата**, чтобы сайт не мог прочитать оригинал из поля, пока идёт обработка.
4. **Набор контрольных документов** с инструкцией «как проверить самому» — для корпоративной оценки.
5. **В 0.6, не сейчас:** маскирование текста, вставленного в поле чата (с одним ключом на разговор для файлов и вставок); перехват `showOpenFilePicker` и `getAsFileSystemHandle`; проверка содержимого ZIP; OCR (решено ранее).

## Что делаем

### Ц1. README: что это и что это не
Над нынешним первым абзацем — блок «Что это» / «Что это не», сценарий из семи шагов, ссылка на раздел «Что расширение не закрывает». Раздел перечисляет: текст, вставленный или набранный в поле чата; способы загрузки в обход поля выбора, перетаскивания и вставки (`showOpenFilePicker`); десктопные и мобильные приложения чатов; сайты без выданного доступа; неподдерживаемые форматы — после 0.5.2 они не уходят молча, но и не обезличиваются; содержимое ZIP, OLE-объекты, макросы VBA, сканы. Английская сводка — тот же смысл в начале. Описание для магазинов (`docs/store/listing.md`) — первая фраза о стороже.

### Ц2. Неподдерживаемый файл не уходит молча
- Перехват берёт любой файл на всех трёх путях (выбор, перетаскивание, вставка), а не только поддерживаемые.
- Неподдерживаемый файл попадает в панель строкой-отказом по образцу скана PDF: «Формат .jpg не проверяется на персональные данные» и «Загрузить как есть». Без этого выбора файл не уходит; «Отмена» — ничего не уходит.
- Смешанный выбор (договор + картинка): одна панель, договор обезличивается, картинка уходит только при «как есть».
- PDF при выключенном перехвате PDF (`pdfMode: 'off'`) — тоже неподдерживаемый: предупреждение с указанием, что перехват PDF выключен в настройках.
- Ключ восстановления по-прежнему не уходит ни при каком выборе; список «не спрашивать» не открывает путь ключу (`.json`, `.txt`, `*.mapping.json` поддерживаются и в список не попадают).

### Ц3. Список «не спрашивать»
Настройки → новое поле: расширения через запятую, файлы которых уходят без предупреждения, как до 0.5.2. По умолчанию пусто. Поддерживаемые форматы в список не добавляются (поле их отклоняет с пояснением). Схема настроек 4 → 5, миграция без действий пользователя.

### Ц4. Поле выбора очищается сразу
`input.value = ''` в момент перехвата; результат (обезличенный файл, «как есть», «оригинал») подставляется в поле явно. Сайт, читающий `input.files` напрямую во время обработки, видит пустое поле.

### Ц5. Контрольные документы
`docs/verify/` — 4–6 документов (`.docx`, `.xlsx`, `.pdf`, картинка) с вымышленными контрольными данными и список «что должно замаскироваться» + инструкция: поставить расширение, прикрепить файлы в чат, сверить. Один документ с намеренно трудными случаями (одиночная фамилия без метки, иностранное имя вне словарей) — показать, что пропуски возможны и как их замаскировать вручную.

## Критерии приёмки

| № | Критерий | Как проверяем |
|---|---|---|
| К1 | Первый экран README (до скриншота) отвечает: что это (сторож), что это не, сценарий 7 шагов; раздел «Что расширение не закрывает» со всеми пунктами Ц1; то же в английской сводке | ревью |
| К2 | Неподдерживаемый файл (`.jpg`, `.png`, `.zip`, `.doc`, без расширения) на выборе, перетаскивании и вставке: обработчик страницы получает 0 событий с файлом до выбора человека; после «Отмена» — 0; после «Загрузить как есть» — ровно исходный файл | e2e на всех трёх путях |
| К3 | Смешанный выбор: страница получает обезличенный документ и картинку только при «как есть» по картинке; без него — только документ | e2e |
| К4 | Расширение из списка «не спрашивать» проходит без панели, как в 0.5.1; поддерживаемые форматы в список не добавляются; ключ восстановления не уходит ни при каком содержимом списка | unit + e2e |
| К5 | Во время обработки `input.files.length === 0`; после «оригинала» и «как есть» в поле ровно исходные файлы (кроме ключа), после обезличивания — обезличенные | e2e |
| К6 | Миграция настроек 4 → 5: все прежние поля сохранены, список пуст | unit |
| К7 | `docs/verify/`: каждый документ прогоняется через расширение, ожидаемые маски совпадают со списком (трудные случаи отмечены как «может пропустить») | ревью + прогон |
| К8 | Справка ru/en, `docs/spec-full.md`, `docs/contracts.md`, `docs/store/listing.md` описывают новое поведение | ревью |
| К9 | `npm test`, `npm run e2e`, `npm run lint` зелёные; CI один раз в конце; сторож размера `content.js` (165 КиБ) — превышение только решением координатора с числом в `docs/tasks.md` | CI |

## Чего не делаем в 0.5.2
Обезличивание неподдерживаемых форматов, проверку содержимого ZIP, текст в поле чата, `showOpenFilePicker`, переобучение модели. Модель остаётся 1.2.1.
